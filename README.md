# Virtual Bookshelf

A browsable, searchable catalogue of my physical books, built from photos of
the shelves. Starts as a store-style library view (covers, author, details);
grows into reading lists, cross-book quote and topic search, and a way to find
the next book to read or buy.

Runs locally on a Mac (MacBook or iMac — either works) with open-source tools. Nothing leaves the machine
except lookups to public book-metadata APIs — and the published cover grid at
**https://sgwoods.github.io/virtual-bookshelf/**, which is part of the
[Steven Woods project portfolio](https://sgwoods.github.io/public/).

**Where things stand:** Phase 1a is done — the spines have been read and
`data/books.csv` holds a first-pass catalogue of 521 items. Phase 1b is
under way: the full Open Library lookup ran on Oct 30 (478 of 521 matched,
494 after a scoring fix), review is next, and the cover-grid site is built
and deployed by GitHub Actions. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for how it
works, [docs/STATUS.md](docs/STATUS.md) for the numbers and
[docs/ROADMAP.md](docs/ROADMAP.md) for what comes next.

## Layout

```
data/
  books.csv          one row per physical book: photo, stack, position,
                     title, author, confidence, notes   ← the catalogue
  books_unique.csv   same, with flagged duplicate copies collapsed
  resolved.csv       lookup results: status, score, work id, year, cover, ISBNs,
                     subjects, top candidates   (generated by resolve.py)
  overrides.csv      your decisions from the review page — always win
  reading.csv        optional, local only (git-ignored): title,status,progress
  drive_files.tsv    Drive file IDs for the 31 shelf photos
scripts/
  fetch_photos.py    get the HEICs from Google Drive into photos/raw/
  heic2jpg.py        HEIC → JPEG using only ffmpeg + Pillow (no libheif needed)
  make_previews.py   batch-convert photos/raw/ → photos/jpg/ (+1600px previews)
  report.py          counts, top authors, review queue from books.csv
  resolve.py         match each book on Open Library (Google Books fallback)
                     → data/resolved.csv
  review.py          local review page and control panel: decisions →
                     data/overrides.csv; buttons for the pipeline steps
  pipeline.py        update / retry / apply / build / test / publish / finish
  build_site.py      cover-grid page → _site/index.html (git-ignored)
site/
  template.html      the page design; build_site.py fills in the data
tests/               python3 -m unittest discover -s tests (no network)
.github/workflows/
  pages.yml          test → build → deploy to GitHub Pages → notify the hub
docs/
  ARCHITECTURE.md    what exists and how it works (checked by tests)
  STATUS.md          dated log: what was done, results, known gaps
  ROADMAP.md         phases, next steps, open decisions
photos/              (git-ignored) raw/ HEICs and jpg/ conversions
```

## Setup

```bash
git clone https://github.com/sgwoods/virtual-bookshelf.git
cd virtual-bookshelf
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
brew install ffmpeg            # only needed for heic2jpg.py; macOS can use sips instead
```

## Reproducing Phase 1a

1. **Photos.** Download the Drive folder into `photos/raw/`
   (see the docstring in `scripts/fetch_photos.py` for three ways).
2. **Convert.** `python3 scripts/make_previews.py --workers 4`
   On a Mac, `sips -s format jpeg photos/raw/*.HEIC --out photos/jpg/` is faster.
3. **Read spines.** This pass was done by a vision model looking at each
   1600px preview and transcribing title/author per spine, zooming into the
   full-resolution JPEG for anything ambiguous. The result is `data/books.csv`.
   To re-run or extend it, see ROADMAP → "Phase 1a tooling".
4. **Check.** `python3 scripts/report.py --review`

## Reviewing and publishing — one page

Needs only the Python 3 that ships with macOS — no installs.

```bash
cd ~/Developer/virtual-bookshelf
python3 scripts/review.py
```

That opens the review page. Work through the cards, then use the buttons along
the top: **Get latest** (pull from GitHub), **Retry lookups**, **Apply
decisions**, **Rebuild site** (opens a preview), **Run tests**, **Save & push**
(commits the data on a review branch and pushes it), or **Finish** — apply,
rebuild, test and push in one go. The log at the bottom ends with the link to
open the pull request; merging it on GitHub redeploys the site.

The same steps without the page:

```bash
python3 scripts/pipeline.py finish
```

`python3 scripts/pipeline.py status` shows where things stand. The original
one-off lookup commands were `python3 scripts/resolve.py --limit 20` (trial)
and `python3 scripts/resolve.py` (full run); `--retry` re-runs weak and none
rows after a scoring change.

Status values in `resolved.csv`: `matched` (score ≥ 0.80), `weak` (0.55–0.80,
goes to review), `none`, `skipped` (unknowns and theses — not looked up),
and after review `confirmed`, `confirmed-unlisted`, `not-a-book`.
A title has to be ≥ 85% similar on its own to count as `matched`, so
*Dune* never silently matches *Dune Messiah*; near-misses go to review instead.

The review page works without the photos on the Mac — each card links to its
photo in Drive. If `photos/jpg/` exists locally it uses that instead.

## The cover grid (published site)

```bash
python3 scripts/build_site.py             # → _site/index.html
open _site/index.html                     # preview
python3 -m unittest discover -s tests     # what CI runs before deploying
```

Pushing to `main` runs `.github/workflows/pages.yml`: tests, builds the page,
adds `build.json` (the deployed commit), publishes to GitHub Pages and asks
the portfolio hub (`sgwoods/public`) to refresh this project's entry.
One-time setup: repository Settings → Pages → Source: **GitHub Actions**; and
optionally a `PUBLIC_HUB_DISPATCH_TOKEN` secret (fine-grained token, repo
`sgwoods/public`, Actions read/write) so the hub refreshes immediately instead
of on its daily run.

Every book appears. Books without a confirmed cover get a titled card marked
"Cover missing" — unless you have published your own image for it (review
page → Add downloaded images / 📚 Add to bookshelf), which then shows with a
small credit naming its source. Reading status comes from `data/reading.csv`, which is
git-ignored: it shapes local previews only and is not published.

## Data conventions (`books.csv`)

| column       | meaning |
|--------------|---------|
| `photo`      | source frame, e.g. `IMG_8884` — doubles as a shelf location |
| `stack`      | which group in the frame: `left`/`middle`/`right`/`far-right`/`stack`/`shelf` |
| `position`   | order within the stack, top-to-bottom or left-to-right; `0` = not a book (DVD, CD, guide) |
| `title`, `author` | as read from the spine; `(ed.)`, `(trans.)` kept in the author field |
| `confidence` | `high` = legible; `medium` = inferred or partly hidden; `low` = needs a look at the shelf; `checked` = corrected by hand in review |
| `notes`      | publisher/format when visible; `second copy`, `overlap`, or `same copy` flags duplicates |

The `photo + stack + position` triple is the book's shelf address until a
proper location scheme replaces it (see ROADMAP, open decisions).
